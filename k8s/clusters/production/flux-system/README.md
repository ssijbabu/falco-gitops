# flux-system

This directory is intentionally **empty of manifests**. It's the install
target for `flux bootstrap`, which generates and manages three files here
that this repo does not hand-author or edit:

- `gotk-components.yaml` — the Flux controllers themselves (source-controller,
  kustomize-controller, helm-controller, notification-controller) plus their
  CRDs. This file is large (all CRDs inline) and version-pinned by Flux's own
  release process — hand-copying it goes stale the moment Flux cuts a new
  release, so it's regenerated by bootstrap/`flux install`, never edited here.
- `gotk-sync.yaml` — the `GitRepository` (named `flux-system`, in the
  `flux-system` namespace) and root `Kustomization` that point Flux back at
  this path in this repo, so it reconciles itself.
- `kustomization.yaml` — a plain `kustomize` `Kustomization` (NOT the Flux
  CRD) listing the two files above, used by `flux bootstrap` internally.

## Bootstrap (private repo, HTTPS + PAT)

Run once per cluster, from a machine with `flux` CLI + cluster-admin
kubeconfig context set to the target cluster:

```bash
export GITHUB_TOKEN=<personal access token, repo scope>   # or GITLAB_TOKEN, etc.

flux bootstrap git \
  --url=https://<git-host>/<org>/<repo>.git \
  --branch=main \
  --path=k8s/clusters/production \
  --username=git \
  --password="$GITHUB_TOKEN" \
  --token-auth=true
```

If the repo is on GitHub specifically, prefer the GitHub-native bootstrap
instead — it manages the token/secret the same way but also handles repo
creation and branch protection:

```bash
export GITHUB_TOKEN=<personal access token, repo scope>

flux bootstrap github \
  --owner=<org-or-user> \
  --repository=<repo> \
  --private=true \
  --branch=main \
  --path=k8s/clusters/production \
  --token-auth=true
```

Either form:
1. Installs the Flux controllers + CRDs into the `flux-system` namespace.
2. Creates a `Secret/flux-system` in that namespace holding the git
   credentials (HTTPS `username`/`password`, the PAT), referenced by the
   `GitRepository` it also creates.
3. Commits `gotk-components.yaml`, `gotk-sync.yaml`, and `kustomization.yaml`
   into this directory and pushes them.
4. Starts reconciling this path — which is what picks up
   `../infrastructure.yaml` and `../security.yaml` (see that directory) and,
   transitively, everything under `k8s/infrastructure/` and `k8s/security/`.

Re-running `flux bootstrap` (same flags) is safe/idempotent — use it to
rotate the PAT (it updates the Secret) or to reinstall after a Flux version
bump (`--version=vX.Y.Z`).

## Verify

```bash
flux check
flux get sources git
flux get kustomizations -A
```
